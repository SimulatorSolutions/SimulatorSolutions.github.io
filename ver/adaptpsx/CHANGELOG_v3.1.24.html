Running changelog for AdaptPSX — the PSX ⇄ Aerosoft MCP / hardware adapter. Version source of truth: src/AdaptPSX/Master.java (version). Format follows standards/APP_STANDARDS.md (B3).

v3.1.24 — 2026-09-20

  • Bugfix (auto-update): the update check now reads its version feed from the GitHub Pages feed the shared Updater publishes (.../ver/adaptpsx/adaptpsx.html). The retired simulatorsolutions.com.au feed served a bogus v B8.0 with no download URL, which triggered a false "new version available / visit website" popup on every launch. Existing Adapt.ini files are auto-migrated off the legacy com.au URL — a blank or com.au value is ignored in favour of the built-in default, while any other custom feed you set is still honoured.
  • Change (About tab): minor layout tidy-up (scroll-pane placement and minimum width).

v3.1.23 — 2026-09-20

  • Feature (auto-update, #601): the About tab gains a working Check For Updates button for an on-demand version check. When you press it and nothing newer is available it now tells you "You are running the latest version", and a feed with no version or a network/URL error shows a dialog instead of failing silently. The automatic check at startup is unchanged — it stays silent unless a newer build is found.

v3.1.22 — 2026-09-20

  • Change (ACARS): the RECEIVED-MESSAGES INDEX page title now reads <label> MSG INDEX, taking the label from the configurable ACARS name that already drives the CDU MENU prompt, instead of the hard-coded HACARS.
  • Change (SATCOM): the Configuration → SATCOM sub-tab is now hidden at startup unless enableSATCOM=true in Adapt.ini, so the still-in-development SATCOM controls stay out of the way by default.

v3.1.21 — 2026-08-31

  • Feature (ADS-C route awareness): new active-route parsing (FmcRoute) reads PSX's live FMC route ahead of the aircraft (CduRteLa Qs407) to derive the Next / Next+1 waypoints and the cross-track distance from the active leg. This is what feeds the v3.1.20 ADS-C waypoint-change (WCE) and lateral-deviation (LDE) event contracts, and it deliberately reads the active route source so "next waypoint" is the true upcoming fix rather than an already-passed one.
  • Chore: added reference documentation for the datalink and SATCOM work — an ICAO Doc 10037 (GOLD) review plus the Honeywell / Cobham / Airbus satellite-comms manuals used to ground the SATCOM page set.

v3.1.20 — 2026-08-31

  • Feature (ADS-C event & demand contracts, #547): ADS-C now answers the full FANS contract set, not just periodic reporting. It accepts REQUEST DEMAND (a single on-request report), REQUEST PERIODIC <sec> (minimum 64 s, default 304 s) and REQUEST EVENTS, and evaluates the four standard event contracts on a 1 Hz tick (ICAO Doc 10037 §1.2.5.3.6): waypoint change (WCE), level-range deviation (LRDE), vertical-rate (VRE) and lateral deviation (LDE). Each event report is tagged with the triggering event; WCE re-fires on every change while the others arm once per contract.
  • Feature (ADS-C emergency mode): a CPDLC emergency downlink automatically drives ADS-C emergency reporting (Doc 10037 §4.6.2) — sending MAYDAY (DM56) or PAN (DM55) arms it, CANCEL EMERGENCY (DM58) clears it. While armed, every position report is tagged EMERGENCY and periodic contracts report at 64 s; onset and cancellation are pushed to every station holding a contract without waiting for the next interval.
  • Feature (richer position reports): an optional rich reports mode (enableRichReports) appends an earth-reference group (true track, ground speed, vertical speed) and a predicted-route group (Next / Next+1 waypoints) to the downlinked reports; the basic position prefix is unchanged so simpler parsers still work.
  • Bugfix (ADS-C altitude): the altitude in ADS-C position reports was 1000× too high — PSX supplies altitude in milli-feet and it was being downlinked as-is. It is now scaled correctly, which also fixes the level-range (LRDE) band comparison.
  • Feature (SATCOM — Honeywell SDU page style): the SATCOM CDU pages can now render in the real Honeywell MCS-4000/7000 (SD-700) SDU layout — SATCOM MAIN MENU → DIRECTORY / CATEGORY NUMBERS, MANUAL DIAL, and a SATCOM SUBMENU covering LOG-ON / GES selection, channel status and the maintenance report pages, with the real wording and symbols. It is selectable from the SATCOM tab ("Honeywell SDU page style", satcomRenderStyle, default Honeywell); the earlier composite page set is kept as a fallback. Both styles drive the same underlying call model.
  • Feature (SATCOM — Honeywell phone directory): the SAT phone book now models the real Honeywell ORT "Cockpit Telephone Numbers" — up to four categories, a per-entry priority (1–4) and a protected / unprotected flag. Unprotected entries render bracketed ([NAME]) and are editable from the CDU CATEGORY NUMBERS page; the standalone directory editor gains a Protected column.

v3.1.19 — 2026-08-28

  • Feature (ACARS REFUELING report): the <HACARS REFUELING page now reads the aircraft weight unit from PSX pin programming (CfgPinProg Qi30, bit 20 0x100000) and labels the WEIGHTS column KGS X 1000 / LBS X 1000, converting the QTY BEFORE / SUPPLIED / ON BOARD / DIFF readouts to the selected unit. DIFF is now ON BOARD − (QTY BEFORE + SUPPLIED) — the uplift discrepancy. On refuel start (Refueling Qi220 0→1) QTY BEFORE snapshots ON BOARD and SUPPLY VOL / SUPPLIED zero. FUEL TYPE now defaults from the PSX FuelType (Qi192 → JETA / JETA1 / TS1 / JETB) and stays crew-overwritable; SUPPLIER defaults to SH.
  • Feature (ACARS FPL DATA report): once at least one field is entered a SEND> prompt appears at 6R and downlinks the report (ACFT TO DISPATCH / FPL DATA REPORT: / BLOCK FUEL / TAXI FUEL / MATOW) to the DISPATCH ACARS-directory address; SEND> then stays hidden until a fresh entry is made. If the DISPATCH entry has no address, NO DISP ADDR shows on the scratchpad and lights the CDU MSG light until the crew clears it (CLR / typing).
  • Change (ACARS REQUEST page): the request-type toggle moves from 5R to 4L (<ATIS / <TAF / <WX, with its title on the line above), freeing 5R as a fifth origin/ICAO slot; the network name no longer prefixes the ATIS request type.

v3.1.16 — 2026-08-27

  • Feature (ADS-C): AdaptPSX now answers Hoppie ADS-C surveillance contracts. It accepts REQUEST PERIODIC <sec>, REQUEST EVENTS and CANCEL from any ground station and downlinks REPORT <flight> <DDHHMM> <lat> <long> <alt> <hdg> position reports — built from the live PSX position feed — back to the requester at the contract interval. Availability is gated by the ADS-C checkbox (enableADSC, on by default) and the aircraft's ADS arm state, read from the native PSX ATC LOGON/STATUS page 5L prompt (SELECT OFF = armed, SELECT ARM = off). Turning ADS off (or unticking the box) drops every contract and stops reporting. New AdsC subsystem + HoppieClient.downlinkAdsC.
  • Feature (ACARS requests): the <HACARS REQUEST page adds ATIS and TAF requests alongside METAR — one shared airport field feeds REQ METAR / REQ TAF / REQ ATIS buttons that run SENDING → SENT. ATIS routes to the network chosen in the new Hoppie network dropdown (VATSIM / IVAO / PilotEdge).
  • Feature (CDU display selection): the ACARS and SATCOM CDU MENU prompts can now be shown per CDU (L / C / R) from the config tab; default is Center only.
  • Bugfix (CDU): page-change blanking now writes the new lines while the screen is blanked, so the old page no longer flashes through; DELETE + a line-select key blanks that entry field, and CLR now cancels a pending DELETE.

v3.1.15 — 2026-08-25

  • Feature (remote printer control): AdaptPSX now handles addon= commands addressed to it, so any PSX client can remotely toggle the master Enable Printer Output. Send addon=adaptpsx;printer;;;enable=1 (on) or addon=adaptpsx;printer;;;enable=0 (off). The change is immediate — no stop/start — because OutputPrinter.printData reads the flag on every job; the GUI checkbox and status label are kept in sync. New Addon.java parses the addon=<dest>;<destsub>;<src>;<srcsub>;<data> wire protocol (dispatched from NetThread, case-insensitive dest); add future remote commands as extra <destsub> cases.

v3.1.14 — 2026-08-25

  • Bugfix (auto-update, #530): the update check now reads the feed key dlurl= (preferring it and keeping updateurl= as a fallback). The shared Updater publishing tool and the sibling apps (Loader / SimMix / SwitchFS) all write dlurl=, so with a tool-generated feed AdaptPSX previously never saw its download URL and fell back to the website dialog instead of self-installing (standards/APP_STANDARDS.md B8).
  • Chore: folds in in-progress MainDialog layout tweaks and a satcom reference note.

v3.1 — 2026-08-24

  • Feature: Hoppie ACARS / CPDLC integration.
  • Feature: Central Aggregator logging (application standard B7) — best-effort, non-blocking error/event forwarding via EventForwarder, gated by a GDPR privacy-consent dialog (LoggingConsent) and disabled by default. EDT crashes are funnelled to the forwarder.
  • Standards: Version numbering moved to major.minor.patch (3.1.0); the auto-update check now compares versions part-by-part instead of as a decimal number, so three-part versions compare correctly and no longer break the update prompt (standards/APP_STANDARDS.md B1/B8).
  • Chore: Build target moved from Java 10 to Java 11 (enables the standard java.net.http.HttpClient used by Aggregator logging; requires a Java 11+ runtime).

v3.0 — 2026-08-21

Version renumbered to 3.0 to end the earlier 1.x / B2.3 numbering confusion — the single source of truth is now Master.version, and the auto-update feed compares against it.

  • Feature: Auto-update hooks with a certificate check on the downloaded build.
  • Feature: Multi-CDU handling; externally-controlled TCAS; PTT passthrough; minimise-to-tray.
  • Bugfix: Printer linefeed; dark look-and-feel; GUI refresh for the autoCopilot setting.
  • Chore: package-for-store target, .appmap.json and commit hook added — app brought up to the Simulator Solutions application standard for WorkHub deploy.
